# 复现与托管说明

本仓库提供两项已完成课程实验的代码、实验设计、结果汇总、图表、报告和教程。原始运行在 Windows、Python 3.12、PyTorch 2.11.0+cu128 与 RTX 4060 Laptop 上完成；原环境包清单见根目录 `environment-lock.txt`。

## 文件范围

- 上传：Python 源码、测试、冻结实验计划、数据选择配置、汇总指标与核验记录、图表、PDF/Word 报告和教程。
- 留在原电脑：原始数据、预处理数组、逐样本预测数组、所有 `runs/` 下的权重与优化器状态、缓存、文档渲染中间文件、运行日志和本地会话交接记录。
- 因此 GitHub 是代码与成果托管，不是完整训练数据和断点备份。已上传的核验记录是原运行的证据；从仓库新克隆后，需取得数据并重新训练才能重新执行依赖权重/预测的评价。
- 部分历史报告含原机器的路径；请将其解释为当时的记录，不必建立相同盘符。新操作以根 README 的相对路径命令为准。

## 环境

在项目根目录创建环境并激活。GPU 版 torch/torchvision 应按照 [PyTorch 官方安装入口](https://pytorch.org/get-started/locally/) 选择适合系统和驱动的构建，然后安装 `requirements.txt` 中剩余依赖。`environment-lock.txt` 记录了原学习环境的全部包，包含与本项目无关的包，不建议在不同机器上直接全部覆盖安装。

断点训练器按系统选择 Windows 的 `msvcrt` 或 Unix 的 `fcntl` 文件锁。完整训练与续训以 Windows 为已验证平台；在 Linux/macOS 上仍需检查依赖、路径和恢复行为，不能宣称已完成跨平台验证。

## 数据准备

MNIST 和 Fashion-MNIST 由 `data.py` 自动下载；划分种子为 2026。只运行教程前可先执行：

```powershell
python -c "from data import prepare_split; prepare_split('fashion_mnist')"
```

汉字数据使用 CASIA-HWDB1.1 官方原始数据中的自选十类，不是教师发放的原十类包。来源与获取规则见 [官方数据说明](HWDB官方数据来源.md) 与 [十类子集说明](HWDB十类子集说明.md)。确认符合数据提供方条件后，在根目录执行：

```powershell
python download_hwdb.py
python prepare_hwdb.py
python verify_hwdb.py
```

气温数据来自 TensorFlow 官方教程提供的 Jena 2009–2016 镜像，原提供方为德国马普生物地球化学研究所。下载及清洗命令：

```powershell
python weather/prepare_data.py
```

该命令生成 `weather/data/source.json` 和 `preprocessing.json` 等记录。数据获取可能受网络、许可、上游可用性影响；本仓库不重新分发原始数据包，不授予第三方数据的额外使用权。

## 正式复现与原记录

1. 先运行 `python -m unittest discover -s tests -v` 检查模型、划分和恢复机制。
2. 图像基础对比运行 `python run_baselines.py --precision amp --models mlp lenet alexnet googlenet resnet18`，完成后运行 `python summarize_baselines.py --precision amp`。
3. Fashion-MNIST 控制实验见 `reports/ablation_plan.json` 与 `run_ablations.py`；该计划中的 `PLANNED_NOT_TRAINED` 是训练前冻结字段，并非当前进度。
4. 气温运行 `python weather/train_weather.py`，全部九次训练完成后运行 `python weather/evaluate_weather.py`。评估器当前要求 CUDA、168 小时输出和完整九次计划。
5. 在新克隆目录做复现；不要让新的结果覆盖自己希望保留的历史记录。汇总程序可能重写已追踪的报告，Git diff 可以帮助识别差异。

源文件使用 `.gitattributes` 禁用自动换行转换，因为断点会检查源码字节哈希。相同随机种子不保证跨设备、版本或平台逐位一致。只保存 `best.pt` 不能精确恢复 Adam；具体恢复边界见教程和训练器。

## 更新自己的 GitHub 仓库

提交前检查 `git status` 和 `git diff --cached`，确认只有希望公开的源码与成果。忽略规则不是内容检查的替代品；不要使用 `git add -f` 将数据、权重或私密配置强行加入。

```powershell
git status
git add README.md
git diff --cached
git commit -m "Update experiment documentation"
git push origin main
```

首次从电脑推送可能需要通过 Git Credential Manager 登录自己的 GitHub。仓库公开并不自动为全部文件授予开源许可证；当前未替作者选择许可证，第三方代码与数据遵循其原有条款。
